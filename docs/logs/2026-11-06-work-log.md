## 一、项目目标与已确定要求

以 Python 常驻服务连接官方 QQBot 与本机 Codex、DeepSeek Harness（DSH），支持私聊和群聊任务、会话恢复、原生问答、取消与结果回传。先 Windows 原生版，再 macOS，最后飞书。

本轮明确的协作要求：

- 依据 GitHub 中的设计和 planning 文件实施，先完成 M0，再推进 M1。
- 每个交付版本的全部项目文件都在 GitHub 备份，使用完整提交文件树和不可覆盖的附注标签；旧版本保留。
- 规划保存在 docs，README 只写项目介绍与实际交付状态，不列设计和阶段规划索引。
- 项目目录内可直接运行离线测试；Windows、模型和 QQ 实测需要单独的真实证据。
- 不把 fixture、空会话协议检查或版本标签等同于阶段验收通过；未通过项保持未完成。
- 不提交密钥、登录信息、真实聊天内容或未脱敏日志；未经授权不合并 PR。

6. 新增 7 项回归，覆盖私聊、群聊、两种同时补发、确认前不发送、恢复拒绝/超时、重复消息和缺少新连接 ACK。完整测试增至 51 项并全部通过，形成 `v0.0.0-m1.2`，更新 PR #2。

## 四、两项 QQ 审阅问题的处理

| 问题 | 原因 | 当前行为 | 证据 |
| --- | --- | --- | --- |
| P1：恢复补发被丢弃 | 只有收到 RESUMED 后才调用身份过滤和消息处理，较早到达的补发被跳过 | 恢复期间先做白名单检查，每个允许会话最多暂存首条消息；RESUMED 后回复，未确认/被拒绝时不发送；重复事件不重复回复 | [补发回归测试](../../tests/probes/test_qq_replay.py)、[修订检查记录](../validation/evidence/2026-11-06/qq-recovery-regression.txt) |
| P2：重连心跳误报通过 | `ack_seen` 沿用旧连接状态 | 每个连接重新观察 ACK，旧连接及未经请求的 ACK 不计为通过 | [网关回归测试](../../tests/probes/test_qq_gateway.py)、提交 `3740147`；补发修复后再次回归 |

两项修改均作用于 [QQ 独立探针](../../tools/probes/qqbot.py)，不代表已完成真实 QQ 平台验收。

```powershell

```
